Usage: rigorkit scan [--dry-run] [--save] [--tools <list>] [<folder>...]

Finds the projects where rigorkit is installed (folders holding
.rigorkit-version, up to 4 levels below each folder) and registers each new
one in ~/.local/state/rigorkit/projects, so rigorkit update can update them.
It first lists every new project with the tools suggested from its folders,
then asks once: y registers all of them with those tools, e asks project by
project (Enter accepts the suggestion, - skips it), n registers none. Copies that
match a 0.1.0 release keep their fingerprint; copies you edited are marked
so later updates ask before replacing them. Projects already registered are
left as they are.

Without folders it scans scan_paths from ~/.config/rigorkit/config
(comma-separated, ~ allowed) and never enters .git, node_modules or the
names in scan_exclude:
  scan_paths=~/workspace
  scan_exclude=archive,dist

Options:
  --dry-run             Show what would be registered; ask and write nothing
  --save                Add the given folders to scan_paths
  --tools <list>        Tools for every new project (claude,codex,cursor,opencode)
  --help                Show this help

Examples:
  rigorkit scan --save ~/workspace
  rigorkit scan
  rigorkit scan --dry-run --tools claude ~/code

Writes:
  New project records in ~/.local/state/rigorkit/projects and, with --save,
  the scan_paths line of ~/.config/rigorkit/config. Nothing inside projects.

Exit status: 2 for invalid options or no folder to scan, 3 when a folder
does not exist.
