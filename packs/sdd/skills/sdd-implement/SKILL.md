# Stage 5
Top 1% senior developer.
1. Full instructions/constitution once per unchanged context; approved plan/tasks and explicitly authorized Bn (or legacy Tn) + RF/scenario/decision/contract refs. Reuse valid in-context text/dependency findings; search then read relevant ranges. No plan => approved spec/rules; artifact-free bug => approved scope/real code. Missing approval => stop.
2. Before edits trace actual dependencies/ALL writers/readers/boundaries/registration/config/dynamic use beyond named paths; no matches≠proof. Share the map across block tasks, recheck affected paths/consumers after edits. Expand capabilities/baselines/full spec-plan for missing refs, uncertainty, changed contracts, critical paths/new impact. Cross-cutting doubts: topic-matched learnings/vault; repo wins. Scope/design change => plan+tasks gate; behavior change => sdd-change.
3. Implement ALL internal tasks of the approved block in dependency order without next-task permission prompts. Never expand to unapproved blocks. Reuse existing; report deferred/out-of-scope work. Stop for unresolved decisions/blockers, necessary user-run checks or new impact. No test edits; needed change => stop for sdd-change (wrong/incomplete spec), then tests stage after renewed approval. Do not weaken tests.
4. Tests-first user evidence required before covered implementation. Give scoped tests/regressions/integration/lint/typecheck/architecture commands when needed; user executes. Missing/unrun evidence stays pending, never forces premature completion. No repeated runs without changes/failure/justified doubt. Use existing summary helpers when available; retain failing IDs/status and pending checks, no raw log dumps.
5. Review combined block diff/new files from confirmed pre-block base, not each task separately, vs constitution/decisions/boundaries/contracts/consumers. arch-reviewer; frontend-reviewer for .tsx/.jsx/app/. Supply scoped refs/dependencies/diff, no transcript; absent=>say+check yourself. Fix introduced highs within block; re-review fixes ONCE plus affected interactions; broader change=>gate. Brief medium/low/pre-existing/limits.
6. Stop at block review with RF coverage/checks/pending evidence and proposed `<message> (<id> <Bn>)` (legacy Tn preserved). Every commit requires explicit approval; next block requires explicit or evidenced standing authorization. Review/green never authorizes commit. No commit chains/push/merge.
DoD: user-green tests and touched lint/typecheck, combined review without introduced highs; mark tasks/block complete only with sufficient evidence. Record pending/implemented separately from verified, update brief resume state. Spec/code same PR; whole change still needs sdd-verify.
